# 模式：给 AI 源码级别的线索

## 什么情况触发

AI 反复在一个 UI 元素上找不到、等不到、定位不到。它试了各种关键词搜索（靠猜），都不对。

## 我怎么做

不跟 AI 继续描述"大概在表单下面"、"好像是动态加载的"——这些模糊描述 AI 用不上。直接去浏览器 F12，看 DOM，找到元素的实际 class 名或 id，然后精确告诉 AI。

## OA 工时填报的例子

AI 想读"应填工时"的汇总表格，试了搜 `hour`、`time`、`summary`、`fill`、等 45 秒、去别的页面找——全部失败。

我没跟它说"你再找找"，而是打开 F12，找到外层容器的 class 是 `sheet-container`，直接告诉它搜这个。

## 为什么有效

AI 对 UI 的理解靠的是 accessibility tree 和 snapshot，不一定包含完整 DOM 信息。但我能看到 HTML 源码。我花 30 秒找准确 class 名，省掉 AI 几十分钟的瞎试。

## 同类场景

- AI 点不动某个按钮 → F12 看实际绑的是什么事件
- AI 找不到某个数据 → 看 Network 面板，告诉它接口 URL，直接调接口而不是扒页面
